# 05: The app follows boards as they start and stop

**What to build:** with Blossom open, the operator starts `vb serve`, and within about a second the app opens that board without a restart. When they stop it, the app goes back to "no board running". When a newer board starts while one is open, the newer one opens, and when it stops, the app falls back to the one still running.

**Blocked by:** 04

**Status:** ready-for-agent

- [x] The core notices token files appearing and disappearing within about a second. Whether it watches the folder or polls it is chosen here, and the reason is written down in this ticket.
- [x] The trigger that makes the core look again is injectable, so no test sleeps.
- [x] Core tests come first: a board starts while subscribed; the open board stops; a newer board starts while one is open; the newer one stops and the older one opens again.
- [x] A UI test asserts that the screen changes when the fake core pushes a new value.
- [x] Verified by hand: start and stop `vb serve` with the app open.

## Comments

Built on 2026-11-20, test-first. The core gained 5 tests and the UI 1.

**It polls, once a second.** The core's `OpenBoardFollower` has one method, `look`. Each call snapshots the token folder, meaning every file with its write time. When the snapshot matches the last one, `look` returns nothing and sends no request. When it differs, `look` finds the open board again and returns it only if it changed. Polling was chosen over FSEvents because:

- it adds no dependency;
- it handles a token folder that does not exist yet, which `vb` creates on its first run, with no extra code;
- one read of a small folder per second costs next to nothing.

FSEvents would only win on idle cost.

**The trigger is the call itself.** The shell calls `look` every second, and the tests call it directly, so no test sleeps. A test also checks that a look finding nothing changed asks the board nothing.

**The shell keeps one following task.** A new subscription, such as a page reload in development, aborts the previous task instead of adding a second one.

**Verified by hand against a real `vb serve`** from `@vercel/board` 0.54.0. Both it and the release build were pointed at a scratch folder through `XDG_CONFIG_HOME`.

- With Blossom open on "No board running", `vb serve` started. Within 1.5 seconds of its token file appearing, the status bar showed the board's address and the owner's handle and name.
- An interrupt sent to the board's own process stopped it. It deleted its token file, and within 1.5 seconds Blossom was back on "No board running".

**Still out of scope, as the spec says: a board that dies without removing its file.** The folder does not change, so Blossom keeps showing that board until the event stream arrives with the sync spike. It does happen. An interrupt sent through `npx` killed a board that way while ticket 04 was being checked. The next launch ignores such a file, because its discovery no longer answers.

The start screen now says "Blossom opens it as soon as it starts."

## Edge cases closed after review

Each one was specified by a failing test first, except the CSS and the CI setting.

- **Redirects are never followed.** reqwest follows them by default, so a local process answering like a board could have sent the core to another address. The client now follows none, and ADR 0013 says so.
- **A look that found no board retries while token files remain.** Before, a board that did not answer in time when its file appeared left the follower at "no board running" until the folder changed again. A look now settles only when it opens a board or the folder is empty. Retrying against stale files costs one refused local connection per file per second.
- **The conventions check reads every JavaScript and TypeScript module**: `.js`, `.jsx`, `.mjs`, `.cjs`, `.mts` and `.cts`, alongside `.ts` and `.tsx`.
- **An extension must be lowercase letters or digits, and not empty.** `icon.PNG` and `notes.` are now reported.
- **The status bar truncates** a long address or name with an ellipsis, and the handle always shows. Checked against a name of about 500 characters.
- **`vb serve` on the start screen can be selected and copied**, although the rest of the window cannot.
- **Every push to `main` gets a CI run of its own.** Its concurrency group is the commit, so quick pushes run side by side and none cancels another. Pull requests share a group per branch and cancel superseded runs. A first attempt only turned off cancelling, which still let GitHub drop a pending run; the pipeline session caught it.
