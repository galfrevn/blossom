# 03: CI and the two size budgets

**What to build:** every push and pull request is checked by GitHub Actions. A change that breaks a rule, a test or one of the two size budgets of ADR 0009 fails there, and every run prints both measured sizes, so a slow drift is visible before it breaks anything.

**Blocked by:** 02

**Status:** ready-for-agent

- [x] A Linux job runs everything in `check` that does not need macOS: the conventions check, the core's formatting, lints and tests, and the UI's lint, types, tests and build.
- [x] A macOS job lints and builds the desktop shell and builds the disk image. It runs only what needs macOS, because macOS minutes cost ten times as much on a private repository.
- [x] The JavaScript budget is the sum of the gzip sizes of the JavaScript files the UI build emits. The job fails above 250 KB.
- [x] The installer budget is the size of the disk image. The job fails above 15 MB.
- [x] Both sizes are printed on every run, passing or not.
- [x] Locally, `check` still runs everything, so a green `check` predicts a green CI.

## Comments

Built on 2026-11-20. The first run, 44824643655, passed both jobs: Linux in 74 seconds and macOS in 363. It printed `the ui's javascript, gzipped: 67.83 KB of 250.00 KB` and `the disk image: 3.17 MB of 15.00 MB`.

- **The repository turned out to be public,** so macOS minutes are not billed. The macOS job still runs only what needs macOS, because it is the slow one.
- **`budgets.sh` measures both budgets.** It exits 1 when one is over and 2 when there is nothing built to measure. The failing path was checked by running it on a 300 KB file that does not compress.
- **The Linux job leaves the `desktop` crate out** of Clippy and the tests, because building Tauri on Linux needs WebKitGTK. The macOS job lints it.
- **The disk image's Finder layout step** is skipped in CI, where Tauri sees `CI` set.
- **Locally, `check` includes the JavaScript budget.** The installer budget needs a full build: `bun run build && sh budgets.sh installer`.
