# 04: First run: the app opens the local board

**What to build:** with `vb serve` running, the operator opens Blossom and sees which board is open, by its address, and who they are on it, by the handle and name the board gives them. With no board running, they see how to start one. Nothing has to be configured. This is the first run of ADR 0012, without the field to paste another address.

**Blocked by:** 02

**Status:** ready-for-agent

- [x] A `blossom` core crate with no dependency on Tauri. It reads the files in `board/local` under `$XDG_CONFIG_HOME`, or under `~/.config` when that is unset, on macOS too. The folder's location is a parameter.
- [x] Only a file whose URL is on loopback is a candidate. A candidate is a local board only when discovery answers at its URL and names that same URL.
- [x] For the board it opens, the core calls `/me` with the file's token, and shows the handle and name from that answer. A refused token means the board cannot be opened.
- [x] With several local boards, the one whose file was written most recently opens.
- [x] The contract has one subscription, the open board. Its value is "no board" or the board's URL with the person's handle and name. It never carries the token.
- [x] The TypeScript types are generated from the Rust types into a single file with no header comment, and `check` fails when that file is stale.
- [x] The desktop shell forwards the subscription over a Tauri IPC channel, under a capability that grants only that.
- [x] The UI reaches the core through one client module with two implementations, Tauri's and a fake core. The open board lives in a store outside React, read with `useSyncExternalStore`.
- [x] Two screens, "no board running" and "board open", with every string in the typed English dictionary.
- [x] Core tests come first and drive the subscription with a temporary folder and a real local HTTP server. They cover no folder, an empty folder, one board, a board that does not answer, discovery naming another URL, a non-loopback URL, a refused token, and two boards.
- [x] UI tests come first and render the app against the fake core, asserting what a person sees on each screen.
- [x] Verified by hand against a real `vb serve`. The size the HTTP client adds is written down in this ticket.

## Comments

Built on 2026-11-20, test-first. The core has 13 tests: nine on opening a board, which add a malformed token file and three boards to the ticket's list, and four on finding the token folder. The UI has 4 tests.

**Checked against a real `vb serve`**, from `@vercel/board` 0.54.0, once the owner allowed running it. Both `vb serve` and the release build were pointed at a scratch folder through `XDG_CONFIG_HOME`, so nothing was written to the owner's `~/.config`.

- `vb serve` wrote its token file there, named by 32 hex characters, as `documentation/research/board.md` says. Its discovery answered as recorded there.
- Blossom's status bar showed `http://127.0.0.1:4100/api/board` and the owner's handle and name, as the real `/me` gave them.
- Stopped from outside with an interrupt through `npx`, the board exited with code 1 and **left its token file behind**. Blossom, opened again, ignored that file and showed "No board running", because discovery no longer answered. Stale files happen in practice, not only in theory.

Before that, while running `vb serve` was still refused, the same path was checked against a Python stand-in that answered discovery and `/me`. It logged one discovery request and then one `/me` request.

**The HTTP client's weight.** The shell's release binary grew from 9.63 MB to 10.89 MB (+1.26 MB), and the disk image from 3.19 MB to 3.68 MB (+0.49 MB).

Decisions made along the way:

- **The generator is ts-rs**, because specta is still a release candidate. The file is assembled from each type's `decl()`, which carries no header, so it is not excluded from the conventions check. It is excluded from Biome, since its formatting is the generator's. To regenerate it: `BLOSSOM_WRITE_CONTRACT=1 cargo test --package blossom --test contract`.
- **reqwest runs without its default features**: no TLS and no system proxy. `no_proxy()` also ignores proxy environment variables, so requests to a local board go straight to it. Every request times out after two seconds.
- **The command's permission is declared in `build.rs`** through Tauri's app manifest. The permission file Tauri generates from it is ignored by git, like `desktop/gen`.
- **"Board open" is the status bar for now.** The main area stays empty until the lenses arrive.
- **The start screen says "Then open Blossom again."** That stays true until ticket 05, which makes the app follow boards as they start.
- **In a browser, the UI runs against the fake core**, showing "No board running".
