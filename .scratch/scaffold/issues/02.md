# 02: The window opens

**What to build:** a contributor runs `bun run dev` and Blossom's window opens. It has its own title bar with the macOS window buttons inset, it can be dragged by that bar, and it shows no white flash in either theme. It is set in Geist and coloured by the identity's tokens, light or dark as the system says. The same UI also opens in an ordinary browser, and `bun run build` makes the installer.

**Blocked by:** 01. It also needs the identity's token file, `ui/theme/tokens.css`, which the identity session writes.

**Status:** ready-for-agent

- [x] A `desktop` crate on Tauri 2, configured in `Tauri.toml`, with the identifier `io.github.galfrevn.blossom` and the product name Blossom. Its icons have one-word names, and it uses no Tauri plugins.
- [x] A `ui` package on Vite (its config named `vite.ts`), React and TypeScript, with `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` and `verbatimModuleSyntax`. Biome formats and lints it, with `noExplicitAny` as an error, and Vitest finds tests in `tests` folders.
- [x] Tailwind 4's theme points at the identity's CSS variables. The token file is imported as it is, and no value is copied out of it.
- [x] Geist, Geist Mono and Geist Pixel are bundled from the `geist` package, and their license ships with the app.
- [x] A content security policy lets the page load only its own bundled assets and talk only to the core over IPC.
- [x] The window stays hidden until the UI has painted, and shows no white flash in light or dark.
- [x] Capabilities grant only showing and dragging the window.
- [x] The conventions check extends to TypeScript, read by a parser that understands JSX, and to CSS. Tests come first: a comment inside JSX is reported, and a URL in JSX text is not.
- [x] `check` also runs Biome, the type check and Vitest.
- [x] `bun run build` produces a disk image.

## Comments

Built on 2026-11-20. Measured: the UI's JavaScript is 68.75 KB gzipped (budget 250 KB), and the disk image is 3.04 MiB (budget 15 MB). The app inside it is 9.4 MB. Checked by launching both the release build and `bun run dev` and screenshotting the window.

Where this departs from the plan, and why:

- **The shell shows the window, not the UI.** It is shown when the page finishes loading, which is after its stylesheet applies, so there is no white frame. The capability therefore grants only dragging, and `@tauri-apps/api` is not a dependency yet. If the page's JavaScript fails, the window still appears instead of staying hidden.
- **Only the dark appearance was checked by eye.** Switching the system's appearance would have changed the owner's settings. Light uses the same mechanism, with the values on `:root`.
- **The title bar is 38px**, with the window buttons at `x = 16, y = 21`. Two screenshots showed the buttons' centre at `y - 2` (18 for 20, 20 for 22), so 21 should put it at the bar's middle; that value was not screenshotted itself.
- **Tailwind's default palette is removed** (`--color-*: initial`), so a component can only use the identity's colours.
- **macOS 13.3 is the minimum.** Tailwind 4 needs Safari 16.4, which is the WebKit of macOS 13.3, and the Vite build targets it.
- **The app's version is 0.1.0**, in the `desktop` crate. Tauri's CLI refuses to build without a version there.
- **The fonts and their license are read through `ui/node_modules/geist/`**, because the package's `exports` do not expose its font files.
- **Biome covers `ui/` and the root JSON only.** Left unscoped, it also reformats the Markdown in `documentation`. It rewrapped three long lines of `tokens.css`; the values did not change.
- **The disk image's Finder layout step uses AppleScript.** The first local `bun run build` asks for permission to control Finder; without it the step times out. With `CI` set, Tauri skips the step, which is what GitHub Actions will do.
- **The small icon sizes are scaled down from the 40-grid drawing.** ADR 0016 wants their own drawings at 16 and 32. Tauri's generator takes one source, so those sizes are for the identity work to supply later.
