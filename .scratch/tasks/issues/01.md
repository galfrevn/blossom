# 01: The replica keeps task events, actors and a task index

**What to build:** as the copy and the feed deliver events, the replica keeps every task event with its actor and time, the latest of every actor, and an index of tasks from their roots. A replica made before this ticket is copied again. Nothing in the UI changes yet.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] The replica keeps each `task.*` event: cursor, type, task ID, actor, `createdAt` and its fields.
- [ ] The replica keeps the latest of each actor by ID, and asks `GET /actors?id=` for an ID it never saw.
- [ ] The task index is updated in the same transaction as the view that changed it.
- [ ] The replica has a schema version; an older one is copied again.
- [ ] Tests come first, against the fake board with a history of every task event, across a copy and a live follow.
