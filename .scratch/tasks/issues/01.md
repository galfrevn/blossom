# 01: The replica keeps task events, actors and a task index

**What to build:** as the copy and the feed deliver events, the replica keeps every task event with its actor and time, the latest of every actor, and an index of tasks from their roots. A replica made before this ticket is copied again. Nothing in the UI changes yet.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] The replica keeps each `task.*` event: cursor, type, task ID, actor, `createdAt` and its fields.
- [x] The replica keeps the latest of each actor by ID, and asks `GET /actors?id=` for an ID it never saw.
- [x] The task index is updated in the same transaction as the view that changed it.
- [x] The replica has a schema version; an older one is copied again.
- [x] Tests come first, against the fake board with a history of every task event, across a copy and a live follow.

## Comments

Built on 2026-11-21 by a subagent in its own worktree, test-first, and integrated by the integrator. The replica suite went to 28 tests and the sync suite to 36.

**What was built.** The copy and the feed put each delivery into a `Batch` (views, `task.*` events, actors), which the replica applies in one transaction.
- **Task events** keep their cursor, type, task, actor, `createdAt`, `reason`, `result`, `for` (as `assigned_to`), `needs`, and the payload's JSON. A cursor delivered twice is kept once.
- **The task index** has one row per task, written only from the root's newest view, so `version` still decides. It also keeps the task's `channel`, which ticket 02's chips narrow by.
- **Actors:** the latest details by ID, from every event's `actor` and every view's `by.actor` and `author`.
- **Reads for the next tickets:** `Replica::task(id)`, `Replica::task_events(task)` and `Replica::actor(id)`.
- **The schema has a version,** 1, in `PRAGMA user_version`. A file with tables and another version is refused, and `keep_in_step` removes it and copies the board again.

**Decisions the spec did not settle:**
- **IDs that task data names without details** (owner, `by`, `for`, the claim's actor, an event's actor) are asked for with `GET /actors?id=`, 100 at a time, before the batch is stored.
- **IDs the board does not list go in `unlisted_actors`** and are never asked for again. Without this, an owner who only writes through profiles would cost a request for every batch on that task.
- **In the feed, a failed `/actors` request counts as a failed stream:** the batch is not stored, and the stream reopens from the cursor before it.
- **`task.expired` has no actor in Board,** so its ID falls back to `payload.by.actor`.
- **The state is kept as Board's string, not an enum,** so a new state in the experimental protocol does not stop the replica.

**Integration.** Rebased onto Flow 01 to 05: the flow's time index, the `arrivals` table and the `channels` table, with their triggers, joined the versioned schema. A replica from before is now copied again, so Flow 01's rebuild of channels for older replicas, and its test, were removed. Verified by hand: the 100,000-message replica of version 0 was copied again into version 1, with 41 actors and 20 channels, and Flow read as before.
