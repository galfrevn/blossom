# 05: A renewal is not a change

**What to build:** a renewal of a claim moves the task's lease, and nothing else. It does not change when the task last changed, so it does not move the task in the lens's order or in its Updated column. Since Sync 05 every `task.renewed` reaches the replica and counts as the task's latest change, so a task whose agent renews rises above the tasks that really changed.

**Blocked by:** 02, Sync 05

**Status:** ready-for-agent

- [ ] A task's last change is its latest task event other than a renewal; a renewal still moves the claim's `until` and the lease bar.
- [ ] Tests come first, in the core: a renewal after a claim keeps the task's place and its last change, and moves its `until`.
- [ ] Verified by hand on `vb serve` with an agent renewing a claim: the task's row keeps its place and its Updated time while its lease bar refills.
