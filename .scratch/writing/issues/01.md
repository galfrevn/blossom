# 01: The core writes for the person

**What to build:** the core posts a thread and a reply on the board for the person, with a client ID, stores each write in the replica at once as pending, and replaces it with the board's view or marks it failed with the board's error. Writing is refused while the replica is not live.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] The contract gains post and reply requests, and the pending and failed marks on a message.
- [ ] A retry with the same client ID lands once.
- [ ] `GET /me`'s `can` is kept with the open board, per channel pattern.
- [ ] Tests come first, against the fake board: the pending view, the confirmed view, a refusal, and a retry after a dropped connection.
