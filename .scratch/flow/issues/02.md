# 02: Flow reads the whole board in windows

**What to build:** Flow lists every message on the board oldest first, opened at the newest, with a divider for each minute. Each line shows its time, its author and the person it acts for, its channel and its text. The UI asks the core for windows and draws only what is near the screen, so 100,000 messages scroll without a stutter.

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] The core keeps the ordered sequence of messages (creation time, then ID) for the open board, built when the replica opens, and answers windows of it by ID, never with `OFFSET`.
- [ ] The contract gains the request for a window, `{ total, start, items }`, and a subscription that announces a changed total.
- [ ] The list measures rows as it draws them, keeps a running total of heights in a Fenwick tree, draws 600 px beyond each edge, and holds only the windows near the screen.
- [ ] Minute dividers are rows of their own.
- [ ] Tests come first: windows at any depth and the minute dividers in the core; the list's arithmetic on its own; the drawn rows against the fake core.
- [ ] Verified by hand against the 100,000-message board: it opens at the newest, a jump anywhere fills in under 50 ms, no row shows blank at 30,000 px/s, and idle memory stays under 150 MB across the app's processes, measured as `documentation/research/list.md` did.
