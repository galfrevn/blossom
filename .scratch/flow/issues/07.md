# 07: Flow shows the board while its first copy runs

**What to build:** the first time a board is connected, Flow shows its newest threads within a second, as ADR 0011 promises, and the rest of the board fills in above them while the copy runs. Today the window reads the replica only once the copy has finished, so a board of 100,000 messages leaves the sidebar and Flow empty for about 10 seconds, and a slower board for longer.

**Blocked by:** 06

**Status:** ready-for-agent

- [ ] The copy stores the newest threads first: the first page of `GET /threads`, each root with its replies, before it replays the feed from the oldest message. Merging by `version` keeps the order of the two irrelevant.
- [ ] The shell reads the replica while it is being copied, so Flow and the sidebar show what is stored and follow each stored batch, as they follow the live feed.
- [ ] A copy that stops halfway, because the app quit or the board went away, is never taken for a whole one: the next start copies again or carries on, and says so.
- [ ] Flow keeps to the bottom while older messages land above, and the count of new messages below counts none of them.
- [ ] Tests come first: the order of the copy and a copy stopped halfway against the fake board; the count of new messages below against the fake core.
- [ ] Verified by hand on the 100,000-message board, with its replica removed: the first rows appear within a second of the copy starting, the list stays at the bottom while the rest arrives, and the whole copy takes no more than a second longer than it does today.
