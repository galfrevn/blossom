# 03: A pre-push hook guards main

**What to build:** a push to `main` is refused locally when the pushed commits break formatting, lint, the conventions check or types. The hook checks only what the push changes and answers in under 9 seconds. There is no pull request between a commit and `main`, so this hook is the gate.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] The hook lives in the repository and is installed by `bun install`, through `git config core.hooksPath`. Nobody has to remember to install it. Check whether bun runs the root's `prepare` script; otherwise use `postinstall`.
- [x] It reads the pushed range from the hook's standard input and finds the changed files.
- [x] It always runs the conventions check, because any new file can break the naming rule.
- [x] When Rust files changed: `cargo fmt --check`, and Clippy with warnings denied on the workspace, the desktop shell included.
- [x] When UI files changed: Biome on the changed files, and the type check on the whole UI, because a change to one file can break the files that import it.
- [x] It runs the commands through the package scripts, so ticket 04 can change a tool without touching the hook.
- [x] It prints how long it took.
- [x] The conventions check accepts `pre-push` as a name git dictates.
- [ ] `CLAUDE.md` gains one line: pushes go through the hook, and `--no-verify` is never used.
- [x] Proven to block. A commit with a formatting error, a misnamed file and a type error is refused, one at a time. A push of documentation only runs just the conventions check.
- [x] The comments below record the time on a warm machine for a documentation push, a UI push and a core push. Each must be under 9 s. If Clippy alone breaks the budget, record it and bring the choice back to the owner instead of dropping it silently.

## Comments

- **How it is built, 2026-11-20.** The hook is `hooks/pre-push`, a POSIX shell script. `bun install` runs the root's `prepare` script, which sets `core.hooksPath` to `hooks`. Bun 1.4.5 runs the root's `prepare`, checked in a scratch package, with and without `--frozen-lockfile`. The checks are root package scripts: `conventions`, `rust:format`, `rust:lint`, `ui:lint` and `ui:types`. `check` is now built from the same scripts, so the hook and `bun run check` cannot drift apart.
- **What counts as changed.** For each pushed ref, the hook diffs the remote's commit against the local one. For a new ref, or a remote commit not fetched yet, it takes the files of the commits that are on no remote. Rust means a `.rs` file, a `Cargo.toml`, `Cargo.lock`, `clippy.toml` or `rustfmt.toml`. UI means anything under `ui/`, or the root `package.json`, `bun.lock` or `biome.json`. Biome reads only the changed files that still exist. The types are checked on the whole UI.
- **The checks read the working tree, so the hook first makes sure the working tree matches what is pushed.** If any file the push changes differs between the working tree and the pushed commit, the push is refused and those files are named. Two sessions sometimes share this working tree, and one can push while the other has edits in progress. Checking a clean export of the pushed commit instead would mean a second build of the desktop shell, which does not fit in 9 seconds. The gap that remains: uncommitted edits to a file the push does not change can still make a whole-UI or whole-workspace check pass or fail. CI catches either case.
- **Proven, on 2026-11-20,** with real `git push`es from a scratch clone to a local bare repository, the hook installed by `bun install`. Each broken commit was refused on its own and then dropped:
  - a Rust line over the width limit: refused by `cargo fmt`;
  - `export const probeSpacing   =  "loose"` in `ui/dictionary.ts`: refused by Biome's formatter;
  - `documentation/research/two-words.md`: refused by the conventions check;
  - a string assigned to a number in `ui/dictionary.ts`: refused by `bun check` with TS2322;
  - a committed file edited again before pushing: refused before any check ran;
  - an unused public function in `core`: refused by Clippy's `dead_code`. This one was not planned.
- **Time on a warm machine.** A documentation push took 0.5 s, every time, and ran only the conventions check. A UI push took 0.9 s; the first one in the clone took 2.5 s. A core push took 1.2 s on three runs; the first core push after warming up took 7.7 s, because it rebuilt the core and the desktop shell for Clippy. All are under 9 s, and Clippy did not break the budget.
- **`CLAUDE.md` is not changed yet.** The line this ticket asks for goes into the instructions every agent reads. Another session handed this ticket over, so the owner confirms that line before it is added.
