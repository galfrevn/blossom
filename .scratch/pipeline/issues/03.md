# 03: A pre-push hook guards main

**What to build:** a push to `main` is refused locally when the pushed commits break formatting, lint, the conventions check or types. The hook checks only what the push changes and answers in under 9 seconds. There is no pull request between a commit and `main`, so this hook is the gate.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] The hook lives in the repository and is installed by `bun install`, through `git config core.hooksPath`. Nobody has to remember to install it. Check whether bun runs the root's `prepare` script; otherwise use `postinstall`.
- [ ] It reads the pushed range from the hook's standard input and finds the changed files.
- [ ] It always runs the conventions check, because any new file can break the naming rule.
- [ ] When Rust files changed: `cargo fmt --check`, and Clippy with warnings denied on the workspace, the desktop shell included.
- [ ] When UI files changed: Biome on the changed files, and the type check on the whole UI, because a change to one file can break the files that import it.
- [ ] It runs the commands through the package scripts, so ticket 04 can change a tool without touching the hook.
- [ ] It prints how long it took.
- [ ] The conventions check accepts `pre-push` as a name git dictates.
- [ ] `CLAUDE.md` gains one line: pushes go through the hook, and `--no-verify` is never used.
- [ ] Proven to block. A commit with a formatting error, a misnamed file and a type error is refused, one at a time. A push of documentation only runs just the conventions check.
- [ ] The comments below record the time on a warm machine for a documentation push, a UI push and a core push. Each must be under 9 s. If Clippy alone breaks the budget, record it and bring the choice back to the owner instead of dropping it silently.
