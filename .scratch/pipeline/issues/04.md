## Comments

All measured on 2026-11-20 on the owner's machine, warm, with Biome 2.6.8, oxlint 1.94.0, oxfmt 0.79.0, `tsc` 7.0.2 and bun 1.4.5. oxlint and oxfmt were installed in a scratch folder and are not dependencies.

### Types

- `ui`'s `types` script is `bun check --project tsconfig.json`. Three runs each: `bun check` 0.03 s, `tsc --noEmit` 0.09 s, both clean on 14 files.
- Seeded with three type errors in one throwaway file (a string assigned to a number, a key missing from the dictionary, a number passed as `StatusBar`'s `openBoard`), both reported the same three errors, at the same positions and with the same codes: TS2322, TS2339 and TS2322. No difference.
- `typescript` stays at 7.0.2, the version `bun -p process.versions.typescript` reports.

### Biome against oxlint and oxfmt

- **Formatting.** With its configuration migrated from Biome (`oxfmt --migrate=biome`), oxfmt agrees with Biome on every file, CSS with Tailwind's directives included. The one difference is `package.json`, whose keys oxfmt sorts (it moves `packageManager` to the end). With its defaults, oxfmt would rewrite 8 of the 21 files.
- **Lint, seeded.** One file of each kind with typical mistakes. A TSX component got 21 kinds, a CSS sheet with `@import "tailwindcss"`, `@theme` and `@apply` got 5, and a JSON file had a duplicate key.
  - Only Biome finds: everything in CSS (a duplicate property, an unknown property, an unknown unit, an empty block, hex colours, properties outside Baseline) and the duplicate key in JSON. oxlint does not read CSS or JSON. Also `useIterableCallbackReturn`, a `forEach` callback that returns a value.
  - Only oxlint finds: `react/set-state-in-effect`, `react-perf/jsx-no-new-object-as-prop`, `unicorn/no-new-array` for `new Array(5)`, `react/hook-use-state`, and `typescript/explicit-module-boundary-types`. In Biome that last one exists only as the nursery rules `useExplicitType` and `useExplicitReturnType`. The rest of oxlint's extras are style: `one-var`, `func-style`, `max-statements`, `import/no-relative-parent-imports`.
  - Both find: unused variables, hooks out of order and missing effect dependencies, `any`, `== null`, `debugger`, non-null assertions, duplicate keys, `var`, `console`, `forEach`, empty blocks, magic numbers, click handlers on static elements, images without `alt`, buttons without `type`, `javascript:` links, `dangerouslySetInnerHTML` and array indexes as keys.
- **Speed.** Before this ticket: Biome 0.04 s for lint and format of 21 files, oxlint 0.03 s, oxfmt 0.04 s. After, with every rule on: Biome 0.25 s. The cost is the `project` and `types` domains, either of which makes Biome scan the dependencies' types. With both off it is 0.04 s again.
- **Decision: Biome stays.** It is one tool for TypeScript, CSS with Tailwind's directives, JSON and formatting. oxlint cannot check the CSS or the JSON, so switching would need two tools or leave those files unchecked. The gaps above are accepted. `explicit-module-boundary-types` is the one that matters, because `CLAUDE.md` asks for explicit types at module boundaries. Revisit when Biome's `useExplicitReturnType` leaves the nursery.

### Every rule on

`biome.json` sets each of the seven stable groups to `error`. That turns on every non-nursery rule with error severity. Under `preset: "all"`, 147 rules would only print as info and 148 as warnings, and neither fails a check. The domains this repository uses are on in full: `project`, `react`, `tailwind`, `test` and `types`. Exceptions sit in an override for every file, because a group set to one severity cannot list rules of its own.

Left off, or narrowed, and why:

- **Domains `astro`, `drizzle`, `next`, `playwright`, `qwik`, `reactNative`, `solid`, `svelte`, `tanstackQuery`, `turborepo` and `vue`.** None of these is used here. Left on, the Solid and Qwik rules flag React's `className` (`noReactSpecificProps`) and its destructured props.
- **`correctness/useImportExtensions`.** It asks for `.ts` in every import, which Node's ESM resolution needs. The UI is bundled by Vite with `moduleResolution: "Bundler"`, which resolves imports without extensions. Turning it on would also need `allowImportingTsExtensions`.
- **`correctness/noUnresolvedImports`.** It reports that `react` has no export `StrictMode`, because it misreads `@types/react`'s `export =`. The type check already fails on a missing module or export.
- **`style/useConsistentTypeDefinitions`**, set to `type`. The code declares object types with `type`, and the rule's default asks for `interface`.
- **`style/useConsistentTestIt`**, set to `test` at the top level and inside `describe`. That is what the tests use, and the rule's default asks for `it`.
- **`suspicious/noConsole`**, with `console.error` allowed. The UI reports a refused IPC subscription with it, and there is no other sink for errors in a webview.
- **`style/noDefaultExport`**, off for `ui/vite.ts` only, because Vite reads its configuration from a default export.
- **Nursery rules.** They are not part of `all`, and they can change without a major release.

Code changed so the rules pass, with nothing turned off for it:

- `noTernary`: the two conditional renders in `ui/application.tsx` use `&&` with a boolean on the left.
- `noImplicitBoolean`: `data-tauri-drag-region={true}`. Tauri 2.12.7's `drag.js` treats `"true"` like the bare attribute.
- `useDomQuerySelector`: `ui/main.tsx` finds the root with `querySelector("#root")`.
- `useBaseline`: unprefixed `user-select` is outside Baseline, because WebKit needs `-webkit-user-select`. The body now uses `@apply select-none`, which Tailwind emits with both properties. Before this, the rule against selecting text may not have applied in the macOS webview at all.
- `useConsistentMethodSignatures`: the types in `ui/core` (`Core`, `FakeCore` and `OpenBoardStore`) use property signatures, which are checked strictly under `strictFunctionTypes`.
