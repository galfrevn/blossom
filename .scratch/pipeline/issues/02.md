# 02: The macOS job splits in two

**What to build:** the macOS work runs as two jobs side by side. One lints the desktop shell, and the other builds the disk image and checks the installer budget. The push's result arrives when the slower one finishes, not when both have run one after the other.

**Blocked by:** 01

**Status:** ready-for-agent

- [x] A `desktop` job runs Clippy on the `desktop` crate with warnings denied.
- [x] An `installer` job runs `bun run build` and `sh budgets.sh installer`, and still prints the disk image's size on every run.
- [x] Each job keeps its own Rust cache. Clippy's check artifacts and the release build's artifacts no longer share one archive of about 500 MB.
- [x] Nothing that ran before is dropped: the Linux job and the two macOS jobs together run everything the old two jobs ran.
- [ ] The comments below record before and after by run ID, warm and with `Cargo.lock` changed. The target is about 1 min 30 s from push to result, warm.

## Notes

- Warm, the old macOS job spent 12 s in Clippy, 33 s compiling the release build and 22 s making the disk image (run 44838946020). Cold, Clippy alone took 78–98 s, and that is the larger saving.
- Building the desktop shell on Linux would need WebKitGTK and would not check macOS-only code, so both jobs stay on macOS.

## Comments

- **Built on 2026-11-20.** The `macos` job became two jobs that run side by side. `desktop` checks out the code, installs the toolchain with Clippy and runs Clippy on the desktop shell. It installs neither bun nor the packages, and it does not build the UI: a debug check reads `devUrl` and never needs `ui/dist`. `installer` installs the toolchain without components, then bun, builds the disk image and checks its size.
- **Each job has its own cache.** `rust-cache` puts the job's id in its key, so `desktop` keeps only Clippy's check artifacts and `installer` only the release build. The first run under the new ids starts cold on both.
- `.github/actions/rust` now takes `components` as optional, because the installer needs none.
- **The first split failed on `main`, run 44846210752 (`9c2467f`).** Tauri's build script checks every bundle resource. `Tauri.toml` bundled Geist's license from `../ui/node_modules/geist/LICENSE.txt`, so without `bun install` the `desktop` job stopped with ``resource path `../ui/node_modules/geist/LICENSE.txt` doesn't exist``. `0b1fe47` fixed the cause instead of putting bun back: the license now lives in the repository at `desktop/licenses/geist.txt`, so building the shell never needs `node_modules`, and Clippy stays free of bun. `installer` passed in the failed run: 301 s cold, on image `20261102.0473.1`.
