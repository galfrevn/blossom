# 06: The workflows are locked down and dependencies watched

**What to build:** the workflows run with the least access they need, every third-party action is pinned to a commit that cannot change under them, and CI fails on a workflow with a known weakness, on a crate with a known vulnerability, or on a license the project cannot ship. Dependabot proposes updates to actions, crates and bun packages, which keeps the project on its latest versions.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] `ci.yml` sets `permissions: contents: read` for the whole workflow. A job that needs more asks for it itself.
- [ ] Every action is pinned to a full commit SHA, `dtolnay/rust-toolchain@master` included. There is no version comment, because ADR 0015's rule applies to workflow files too.
- [ ] `actions/checkout` runs with `persist-credentials: false`.
- [ ] zizmor checks the workflows in the Linux job, and the job fails on any finding.
- [ ] cargo-deny checks advisories, licenses, bans and sources in the Linux job, configured in `deny.toml`. The allowed licenses are the ones that can ship inside an Apache-2.0 app (ADR 0008). Each exception is listed with the crate that needs it.
- [ ] `.github/dependabot.yml` covers `github-actions`, `cargo` and `bun`, weekly and grouped per ecosystem. Commit messages follow `CLAUDE.md`: Conventional Commits, all lowercase. Check what Dependabot actually writes.
- [ ] Proven. A workflow with a template injection fails zizmor, and a crate under a disallowed license fails cargo-deny. Neither is committed.
- [ ] The comments below record the Linux job's time before and after. The new checks must add less than 10 s.
