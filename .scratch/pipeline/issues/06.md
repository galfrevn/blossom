# 06: The workflows are locked down and dependencies watched

**What to build:** the workflows run with the least access they need, every third-party action is pinned to a commit that cannot change under them, and CI fails on a workflow with a known weakness, on a crate with a known vulnerability, or on a license the project cannot ship. Dependabot proposes updates to actions, crates and bun packages, which keeps the project on its latest versions.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] `ci.yml` sets `permissions: contents: read` for the whole workflow. A job that needs more asks for it itself.
- [x] Every action is pinned to a full commit SHA, `dtolnay/rust-toolchain@master` included. There is no version comment, because ADR 0015's rule applies to workflow files too.
- [x] `actions/checkout` runs with `persist-credentials: false`.
- [x] zizmor checks the workflows in the Linux job, and the job fails on any finding.
- [x] cargo-deny checks advisories, licenses, bans and sources in the Linux job, configured in `deny.toml`. The allowed licenses are the ones that can ship inside an Apache-2.0 app (ADR 0008). Each exception is listed with the crate that needs it.
- [x] `.github/dependabot.yml` covers `github-actions`, `cargo` and `bun`, weekly and grouped per ecosystem. Commit messages follow `CLAUDE.md`: Conventional Commits, all lowercase. Check what Dependabot actually writes.
- [x] Proven. A workflow with a template injection fails zizmor, and a crate under a disallowed license fails cargo-deny. Neither is committed.
- [ ] The comments below record the Linux job's time before and after. The new checks must add less than 10 s.

## Comments

Done on 2026-11-20 with zizmor 1.32.0 and cargo-deny 0.22.0, the latest releases. Both were also run locally, zizmor through `uvx` and cargo-deny from its release archive.

- **Permissions.** `ci.yml` sets `contents: read` for the whole workflow, and no job asks for more.
- **Pins.** `actions/checkout` v7.0.1 is `3d3c42e5aac5ba805825da76410c181273ba90b1`. `Swatinem/rust-cache` v2.9.3 is `d1527c8f67ef9af357290475d4af4b0fab8f12e0`. `oven-sh/setup-bun` v2.2.0 is `0c5077e51419868618aeaa5fe8019c62421857d6`. `taiki-e/install-action` v2.90.6 is `75a7c0f87bd666af3cdb75c5b9e9d03ab6044e6f`. None carries a version comment.
- **`dtolnay/rust-toolchain` is gone rather than pinned.** zizmor's `superfluous-actions` audit points out that the runners already ship rustup, and the action's `master` is a branch, so its SHA matches no tag (`stale-action-refs`). `.github/actions/rust/action.yml` now runs `rustup toolchain install --profile minimal` and `rustup default` itself. That is one less third party in the chain. The workflow sets `CARGO_INCREMENTAL=0` and `CARGO_TERM_COLOR=always`, which the action used to export, so the Rust cache key stays the same.
- **The local action uses `$/.github/actions/rust`,** GitHub's self-repository syntax (July 2026). zizmor's `self-repository` audit asks for it: unlike `./`, it cannot load an action changed on disk by an earlier step, and GitHub counts it as pinned. actionlint 1.7.12 does not know the syntax yet. It is not part of CI.
- **zizmor** runs online in the Linux job, with the job's read-only token, so the audits that need GitHub's API run too, such as the one for impostor commits. On these workflows it reports nothing. With the default persona it hides six findings, all `ref-version-mismatch`, which asks for the version comments ADR 0015 forbids. Locally it took 1.5 s.
- **cargo-deny** reads `deny.toml`. It checks the graph for `aarch64-apple-darwin`, which ships, and `x86_64-unknown-linux-gnu`, where CI builds the core.
  - Advisories: vulnerabilities and yanked crates fail. A crate marked unmaintained fails only when the workspace depends on it directly (`unmaintained = "workspace"`), because nothing can be done about one deeper in the graph. Today that is `proc-macro-error` (RUSTSEC-2024-0370), which comes through Tauri's GTK stack on Linux.
  - Licenses allowed, all permissive and fine inside an Apache-2.0 app: `Apache-2.0`, `Apache-2.0 WITH LLVM-exception`, `BSD-3-Clause`, `MIT`, `Unicode-3.0` and `Zlib`. Crates under `MIT OR Unlicense` or `CC0-1.0 OR MIT-0 OR Apache-2.0` pass through one of them.
  - The exceptions, `MPL-2.0`, each with the crate that needs it: `cssparser`, `cssparser-macros`, `dtoa-short` and `selectors`, through Tauri's HTML handling, and `option-ext`, through `dirs`. MPL-2.0 is copyleft per file: the app can ship them, and their source stays available on crates.io.
  - Bans: wildcard versions fail, except path dependencies inside the workspace. Duplicate versions are allowed, since Tauri's tree has many and none of them is ours to fix.
  - Sources: only crates.io. Any other registry or git source fails.
  - The workspace's own crates had no license, so cargo-deny called them unlicensed. The root `Cargo.toml` now sets `license = "Apache-2.0"` once, and `core`, `desktop` and `conventions` inherit it. `Cargo.lock` did not change. Locally a full `cargo deny --locked check` takes 0.9–1.0 s.
- **Dependabot** covers `github-actions` (the workflows and `.github/actions/rust`), `cargo` and `bun`, weekly, each in one group (`actions`, `crates`, `packages`).
  - Commit messages use the prefix `ci` for actions and `build` for the others, with the `deps` scope. Real Dependabot commits elsewhere with the same settings read `build(deps): bump the cargo group across 1 directory with 8 updates`: the subject is all lowercase. Their bodies start with `Bumps the cargo group …`, list the packages with their own capitals, and end with Dependabot's metadata. The body cannot be configured, so the subject is the only part that follows `CLAUDE.md`.
  - Each ecosystem waits 7 days after a release before proposing it (`cooldown.default-days`). zizmor's `dependabot-cooldown` audit fails under 7, and a release that turns out to be compromised is usually pulled within days. That conflicts in part with keeping everything on its latest version, by a week at most. Security updates skip the cooldown.
- **zizmor and cargo-deny are pinned in the workflow** (`zizmor@1.32.0`, `cargo-deny@0.22.0`). A new release can add an audit, and that would turn `main` red on a commit that changed nothing. Dependabot does not see these two versions, so bumping them is a manual commit.
- **Proven,** in a scratch copy of `.github`, not committed.
  - A workflow running `echo "${{ github.event.pull_request.title }}"` made zizmor exit 14, with `template-injection` on `pull_request` and also `dangerous-triggers` on `pull_request_target`. Without it, zizmor exits 0.
  - A copy of `deny.toml` without `Zlib` made `cargo deny check licenses` exit 4: `foldhash`, which is Zlib only, was rejected.
