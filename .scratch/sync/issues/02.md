# 02: Keep the replica live

**What to build:** once the copy is done, the replica follows the board's feed. A message an agent posts reaches the replica in under a second, and so do edits, deletions, reactions, labels and task changes. When the board closes the stream, as `vb serve` does about every 280 seconds, the core reconnects by itself, resuming exactly where it left off. The status bar says "100,006 messages" while live and "Reconnecting" while it is not.

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] The core follows `GET /events` over SSE with `Last-Event-ID` set to the replica's cursor, and stores the cursor as it goes.
- [ ] A closed stream reconnects at once; a failed connection retries with a growing pause and reports reconnecting.
- [ ] The replica's state gains live and reconnecting, and "copied" is replaced by live.
- [ ] Tests come first against a fake board whose SSE stream ends after a few frames, standing in for the board closing it: every event arrives once, in order, across the reconnection.
- [ ] Verified by hand: a post reaches the replica in under a second, and the replica keeps in step across one of `vb serve`'s stream closes.
