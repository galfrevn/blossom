# 01: Copy the open board into its replica

**What to build:** when a local board opens, the core copies it whole into a replica on disk, and the status bar says how far along the copy is ("Copying 42,000 of 100,006") and then how many messages the replica holds ("100,006 messages"). Nothing in the app reads the replica's content yet.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] A replica per board in a folder the core is given: the app's data folder in the shell, a temporary folder in tests. It is stored through `rusqlite` with SQLite bundled (ADR 0011).
- [x] The replica keeps each message's latest view. A view with a higher `version` replaces the stored one; a lower or equal one changes nothing.
- [x] The copy reads the feed position and every thread root from `GET /threads`, takes the total from `GET /channels`, then replays `GET /events` from the root created first. Cursors are never counted with.
- [x] SQLite runs off the async runtime's worker threads, one transaction per batch.
- [x] The token stays in the core: neither the replica's file nor the page ever holds it.
- [x] The contract gains a second subscription, the replica's state: copying, with how many messages are stored and the total, or copied, with how many are stored. The UI's status bar shows it.
- [x] Replica tests come first, against a real SQLite file in a temporary folder.
- [x] Copy tests come first, against a fake board that pages `/threads`, `/channels` and `/events` the way Board does: a whole copy, and an edit that arrives during the copy.
- [x] UI tests come first: the status bar shows each state.
- [x] Verified by hand against a real `vb serve` holding 100,000 messages. The copy's time and the size `rusqlite` adds to the disk image are written down here.

## Comments

Built on 2026-11-20, test-first. The core gained 13 tests (replica 5, copy 5, follow 1, and the contract), and the UI 4.

**Measured against a real `vb serve`** holding 100,006 messages in 20 channels, on an Apple M3 Pro:

- **Copy time.** The app copied the whole board in 12.8 seconds from launch. That includes opening the window, finding the board, reading every thread, taking the total from `/channels`, replaying the feed and writing it to SQLite. The status bar went from "Copying 22,357 of 100,006" to "100,006 messages".
- **Size on disk.** The replica takes 96 MB.
- **No credentials.** The token, 277 characters long, appears 0 times in the replica's file.
- **Installer.** The disk image grew from 3.52 MB to 4.55 MB with SQLite bundled; the release binary is 14.75 MB.
- **Memory.** The core's process has a physical footprint of 31 MB with no board open and 45 MB with the 100,006 messages copied. Its resident size reads 108 and 124 MB, but most of that is system frameworks shared with every other app. WebKit's own processes added 85 to 100 MB resident (content 39 to 54, GPU about 30, networking 15); `footprint` cannot read them without privileges. ADR 0009's 150 MB for idle memory doesn't say which number or which processes it counts. The list spike should settle that before the budget is judged.

Decisions made along the way:

- **The copy ends when the feed's cursor stops moving,** not when a page comes back without messages. A page can carry only bookkeeping events, and a test covers it.
- **A version-rule test at the copy level was dropped as misleading.** A replay of a consistent board always ends on each message's newest view, so the copy alone never needs the rule. The rule matters once the live feed and restarts meet the copy (tickets 02 and 03), and the replica's own tests cover it.
- **Counts travel as `u32`.** ts-rs turns a `u64` into a TypeScript `bigint`, which serde's JSON number wouldn't match.
- **The board's address and token travel together** as `BoardAccess`, which never shows its token: the token is readable only inside the core, and the type has no `Debug`.
- **The replica's file is named after the board's address** for now. Ticket 03 adds the oldest message, so two projects on one port don't share a replica.
- **The shell keeps one task per job,** each replaced when a page subscribes again: following the open board, forwarding the replica's state, and copying. Only the latest replica state crosses to the page, so a burst of progress becomes one update.
- **The UI's store is generic now** (`createStore` and `useStore`), since a second subscription arrived.
- **Building the shell no longer needs `node_modules`.** CI's desktop job showed that the Geist license was bundled from there; it now lives at `desktop/licenses/geist.txt` (0b1fe47).
